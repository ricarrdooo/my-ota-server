使用指南 · 02 / 20

先分清设备和三类凭据

产品组织项目，硬件型号描述兼容板型，设备代表一台实体板子。已有型号下新增板子，通常只需添加设备。

凭据用途
管理员登录密码人登录网页后台，自己设置；忘记后在服务器电脑重设。
设备访问密钥板子访问 OTA 平台，创建设备或轮换时只显示一次，填入设备设置页。
签名私钥及保护密码本机签名，设备不填写；浏览器记住后通常无需重复导入，加密文件首次导入仍需原密码。

同一型号的设备可共用签名信任，每台设备的访问密钥仍独立。

开始使用 · 03 / 20

启动后台并登录

在运行后台的电脑上打开 PowerShell，执行下面两行。保持启动窗口运行，看到就绪提示后，打开窗口打印的 HTTPS 地址。

cd 'F:\Code\esp32\My OTA Server'
.\scripts\start-public.ps1
  1. 1输入管理员账号 admin
  2. 2输入你设置的登录密码
  3. 3进入工作台

账号通常是 admin，密码使用自己设置的登录密码。没有统一的默认密码。

完成后应看到

登录后进入工作台，顶部出现“已同步”及时间。

若提示脚本被禁止，改用 powershell -ExecutionPolicy Bypass -File .\scripts\start-public.ps1。若服务已在运行，直接打开现有地址，不重复启动。

首次接入 可跳过已有配置 · 05 / 20

为新项目创建产品

产品是一组设备的项目名称。例如“桌面伴侣”是产品，“书桌上的一台板子”是设备。已有 ESP32 产品时直接沿用，不必为每次升级新建产品。

  1. 1填写便于识别的产品名称
  2. 2填写唯一英文标识
  3. 3保存产品

产品名称方便人识别；产品标识供软件使用，按项目约定填写。新项目的签名密钥和硬件配置由维护人员准备。

完成后应看到

产品与硬件页面出现新的产品卡片。

同一产品可以有多个硬件型号，同一型号可以有多台设备。设备数量增加时通常只需再添加设备。

首次接入 可跳过已有配置 · 06 / 20

选择与板子一致的硬件型号

硬件型号决定哪些固件允许安装。当前板子的主控是 ESP32-S3，ST7735S 是屏幕驱动芯片；不要把屏幕芯片填作主控型号。

  1. 1先核对硬件型号与标识
  2. 2导出公开配置给设备开发者

已有“ESP32-S3 桌面伴侣”型号时直接使用。新型号的芯片、应用项目名、分区布局、容量及公钥等参数应由固件开发人员提供。

完成后应看到

型号名称、主控和板子一致；能够导出对应的公开配置文件。

型号页能力标签来自公开配置声明，不是实机诊断结果。回滚以固件和引导程序的实际配置为准；已有型号不要随意修改能力、主控或分区参数。

首次接入 · 07 / 20

把一台板子添加到平台

打开设备页面，添加一个设备。名称可填写“书桌上的设备”，硬件型号选择这块板子对应的型号，日常使用一般选择 stable 通道。

  1. 1设备名称按位置填写
  2. 2选择匹配的硬件型号
  3. 3一般选择 stable
  4. 4保存设备

设备名称可自定义；硬件型号和通道会影响该设备能获得的发布。新增一台实体板子应新增一个设备记录。

完成后应看到

设备列表中出现这台设备，并弹出保存凭据窗口。

只把设备添加到平台，还不会让空白板子自动联网。新板第一次使用前，需要开发人员通过 USB 烧录支持本平台的基础固件。

首次接入 · 08 / 20

立即保存设备标识和访问密钥

设备访问密钥只在创建或轮换时显示。关闭弹窗前先保存设备标识，再复制访问密钥，随后填到设备的设置网页中。

  1. 1设备设置页填这个设备标识
  2. 2访问密钥仅首次显示
  3. 3复制并妥善保存

ESP32 直接联网时，设备设置页填写“设备 / 代理标识”所对应的设备标识；不要误填另列的“联网代理标识”。截图中的敏感值是演示占位。

完成后应看到

你已单独保存这台设备的设备标识和访问密钥。

如果已关闭弹窗又找不到密钥，可以轮换凭据。旧密钥会立即失效，须把新密钥同步到设备，才能恢复连接。

首次接入 · 09 / 20

在设备网页填写 OTA 配置

板子接入 Wi-Fi 后，短按 BOOT 切到“设备设置”页，扫描屏幕二维码或打开屏幕上的 IP。手机或电脑须能与板子在同一局域网互访。

  1. 1填服务器根地址，不带 API 路径
  2. 2填设备标识，不是代理标识
  3. 3首次填写设备访问密钥
  4. 4保存 OTA 配置

勾选启用服务。服务器地址填启动窗口输出的 HTTPS 根地址；设备标识与访问密钥来自上一页。地址不带 /api 路径。保存后等待设备回报。

完成后应看到

平台显示设备最近在线，并逐步出现实际版本；设备页最近请求为 HTTP 200。

图中的 https://ota.example.com 只是示例，不能直接照填。同一设备以后更换服务器地址，密钥留空可沿用；首次配置、更换设备标识或轮换密钥时必须填写对应密钥。

准备固件 首次导入一次 · 10 / 20

让浏览器记住签名权限

打开“打包并上传”，选择设备。在首次导入签名私钥的区域选择对应的 private.pem，并执行导入；若原文件加密，首次导入仍需它原来的保护密码。

  1. 1选择对应硬件的 private.pem
  2. 2加密文件仅首次输入保护密码
  3. 3导入后由当前浏览器记住

登录密码不能解锁签名私钥。签名用于证明固件来自可信发布者；设备访问密钥则用于让设备访问后台，两者用途不同。

完成后应看到

页面提示“本机签名已就绪”。同一浏览器和网站地址下，后续通常无需重复选择私钥。

记忆按浏览器和网站地址保存。临时域名变化、换浏览器或清理网站数据后，可能要重新导入。忘记保护密码时，保留原浏览器记录并联系维护人员协助，不要随意重新生成密钥。

日常操作 从这里开始 · 11 / 20

选择设备和应用固件并上传

先在开发工具中编译出应用固件。打开固件页面的“打包并上传”，选择设备、选择应用 .bin，填写本次更新内容，再执行打包上传。

  1. 1选择要更新的设备
  2. 2选择编译生成的应用 bin
  3. 3写清本次更新内容
  4. 4打包并上传

本项目应用文件为 F:\Code\esp32\00_BASIC\build\00_BASIC.bin。不要选择 bootloader.bin、分区表、ELF 文件或合并烧录包。

完成后应看到

浏览器完成检查、摘要计算和本机签名，平台收到并验证该固件。

版本默认读取 bin 内置版本，例如 V1.0.8。想发布 V1.0.9 时先修改项目版本并重新编译，不能只改文件名。签名私钥和保护密码不会随固件上传。

日常操作 · 12 / 20

检查打包和上传结果

上传完成后，核对版本、硬件型号、文件大小和完整摘要；更新说明可到固件库另看。这里只表示文件已经入库，还没有向设备下发安装指令。

  1. 1上传成功还不等于已发布
  2. 2确认发布到 stable 通道
  3. 3确认后设备才能检查到此版本

如果显示固件已存在，先核对版本和构建摘要，不必反复上传同一文件。相同版本名可以对应不同构建，应结合说明和摘要识别。

完成后应看到

固件验证通过，页面提供发布入口，或可以在固件库中找到该文件。

打包失败时先按页面提示处理。签名型号不匹配、文件不完整或选错 bin 时，应更正输入，不要跳过校验。

日常操作 · 13 / 20

确认要给设备提供哪个版本

在固件库点击“发布此固件”，或在上传成功页面继续确认发布。核对固件版本和发布通道后提交。

  1. 1可从固件库再次发布
  2. 2手动管理不再需要的文件
  3. 3下次更新从这里开始

同一硬件型号、同一通道通常只有一个活动发布。发布会影响该型号和通道下的设备，不只影响刚才打包时选择的那一台。

完成后应看到

版本发布页面出现该版本，并显示“活动发布”；设备升级确认窗口能读到它。

上传是存文件，发布是选择可供下载的版本，下发升级才是让具体设备执行。发布本身不会立即强制所有设备重启。

日常操作 · 14 / 20

在网页下发升级指令

进入设备列表，找到要操作的设备，点击“立即升级”。再次核对设备名称、当前版本和待升级版本，选择等待时间后确认。

  1. 1核对当前版本与待升级版本
  2. 2默认等待 15 分钟
  3. 3确认升级后等待设备领取

默认等待时间是 15 分钟。设备离线时可以先排队；设备联网并领取指令后才会执行。当前固件需支持远程指令，本项目 V1.0.7 起支持。 等待时限用于开始执行前，已开始的下载不会到时强制中断。

完成后应看到

出现“指令已提交”，随后进入设备已接收或正在执行。此时仍需等待最终结果。

如果按钮提示需要更新固件，应先安装支持远程控制的基础版本。确认前若发现待升级版本比当前旧，先核对活动发布，避免误降级。

日常操作 · 15 / 20

等到执行成功再算完成

保留弹窗查看进度，也可以关闭后打开“控制记录”。真正完成需要设备下载、校验、重启，并由新版本通过启动自检后回报。

  1. 1以执行成功作为完成依据
  2. 2以后可在控制记录里查询
  3. 3打开这次升级的详细记录

看到“已提交”或“正在执行”都不是最终成功。完成后检查“执行成功”，并核对设备上报的实际版本。

完成后应看到

控制记录显示执行成功；设备当前版本与目标一致；升级记录显示升级成功或 confirmed。

设备约每 15 秒领取指令，网络请求与重试会增加等待时间。界面刷新慢时先刷新记录，不要连续创建新的升级或重启指令。

查看结果 · 16 / 20

用升级记录定位失败发生在哪一步

在升级记录中找到本次升级，打开事件详情。按时间顺序查看下载、校验、安装、等待启动确认和最终结果。

  1. 1先下载固件
  2. 2启动确认后才是升级成功

等待启动确认表示新程序还没有完成自检。HTTP 0 表示没有收到 HTTP 响应；HTTP 200 也只表示相应请求成功，不代表整次升级已经完成。

完成后应看到

末尾为“升级成功”，再回到设备列表核对新版本。平台已在启动确认时核验版本与完整摘要。

当前板子已启用首启回滚：新版本未确认就失败时可恢复可用旧版本。它依赖旧固件和引导程序完好，不等于能分析所有崩溃原因。

日常操作 · 17 / 20

远程重启一台设备

在设备列表点击“重启设备”，核对设备名称后确认。重启期间屏幕和连接会短暂中断，联网恢复后设备才会回报结果。

  1. 1先确认设备名称
  2. 2离线时可排队等设备上线
  3. 3确认重启，联网补报后成功

重启是重新运行当前程序，不会恢复出厂设置，也不会清除已经保存的 Wi-Fi 和 OTA 配置。

完成后应看到

该条重启指令显示执行成功，设备重新出现最近在线。

同一设备已有未完成指令时先等待结果。即使网页回复丢失，也先查看控制记录；系统会按同一指令标识去重，避免反复重启。

维护与管理 · 18 / 20

手动清理不再需要的固件

固件库按手动方式管理，不会自动只保留最近五份。清理时找到准确的版本和构建，点击“删除此固件”，先看预览中的影响和阻止原因。

  1. 1先检查影响范围与受保护原因
  2. 2核对后确认，或取消保留

活动发布先到版本发布页撤回。删除发布记录不会释放 bin 文件；已有升级历史的发布不能删除。按预览提示处理引用，进行中的下载和待执行指令引用也会阻止删除。

完成后应看到

目标文件已被删除，固件库与发布页面显示更新后的状态；保留的历史可能显示“固件已删除”。

已安装到设备上的程序不会因为服务器文件被删除就消失。但服务器删除后，后续无法再下载该文件。不要只凭相同版本名判断是同一份构建。

使用指南 · 19 / 20

更换地址 电脑和常用维护

临时域名变化后，以启动窗口显示的新 HTTPS 地址为准；同一设备只改服务器地址，访问密钥留空沿用。

换电脑先完整备份旧后台数据目录、固件与私钥备份，再按部署说明迁移。电脑采集服务的 IP 和密钥在设备设置页单独修改。

忘记管理员登录密码

在服务器电脑运行下面命令，按提示输入两次新密码，至少 12 个字符。终端不显示输入字符是正常的。重设会注销旧网页会话。

cd 'F:\Code\esp32\My OTA Server'
.\.venv\Scripts\python.exe -m ota_server reset-admin

遇到问题按提示逐项排查

页面打不开确认后台与隧道运行，核对最新地址。
设备离线确认供电、Wi-Fi、服务器地址、设备标识和访问密钥。
HTTP 401核对设备访问密钥，轮换后必须同步到板子。
HTTP 0 或连接超时检查网络、地址、校时和隧道，稍后刷新记录。
签名未导入浏览器和网站地址有区别；导入原私钥或请维护人员协助复用原浏览器记录。
指令未完成查看控制记录，区分等待、执行、过期和真正成功。
不能删除按删除预览处理引用和进行中的升级，不强删文件。
