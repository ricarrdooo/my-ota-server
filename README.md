# OTA Station · 个人通用 OTA 服务器

面向个人设备的独立固件发布工作台：Vue 3 桌面前端 + FastAPI + SQLite + 本地文件存储 + Caddy HTTPS，提供中文管理后台和版本化设备 API。所有服务器代码、部署配置和测试均在本目录，不依赖原 ESP32 工程。

图文操作手册（含编号、框线和箭头标记）：[PDF 版](docs/user-manual.pdf) · [离线网页版](docs/user-manual.html)。首次接入看第 5–10 页，日常上传、发布和升级看第 11–16 页。

## 已实现 / 边界

- 产品、不可变硬件配置、设备、网关及授权子设备管理；stable / beta 通道。
- 网页本地 RSA 签名与离线命令行签名，服务器只保存公钥；上传时独立验证签名、摘要、板型、布局、容量和镜像格式。
- 固件上传与发布分离；同一板型、通道只有一个活动发布，可撤回、重新发布。
- 每设备 / 网关独立 Bearer 凭据，仅首次显示，可轮换、停用；网关不能访问其他网关的子设备。
- 固件下载需要绑定升级尝试，支持 HTTP Range；发布被替代后，已绑定下载可继续 24 小时，公钥吊销立即阻断。
- 幂等升级尝试、带序号的事件、严格状态流转；应用启动确认匹配版本和摘要后才计为成功。
- 网页下发升级与重启、设备主动领取、持久化队列、请求去重、过期和执行结果；设备需实现远程命令 v1，见 [远程命令](docs/remote-commands.md)。
- 单管理员、Argon2 密码哈希、HttpOnly 会话、CSRF、来源检查、请求体限制和进程内限流。
- 数据库一致性备份工具、Docker Compose / Caddy 公网部署配置。

这是单实例个人版，不是已部署的云服务。暂未实现多管理员、自动灰度、消息推送、差分升级、自动垃圾清理、密钥轮换信任链或硬件远程烧录。

### 芯片兼容不等于已经实现硬件升级

| 镜像适配器 | 服务端实际检查 | 设备侧仍需提供 |
| --- | --- | --- |
| `esp-idf-app` | ESP 应用头、chip_id、项目、应用版本、段边界、校验和和追加 SHA-256 | HTTPS 客户端、签名清单验证、OTA 分区、安全启动确认 |
| `mcuboot-image` | 未加密单应用格式、头部布局、TLV 边界和 SHA-256 | 已正确配置的 MCUboot、原生签名验证和升级客户端 |
| `raw-cortexm` | 对齐长度、初始栈、Thumb 复位向量、目标应用与 RAM 范围 | 定制 Bootloader、暂存区、完整签名验证和可靠安装协议 |

MCUboot 的原生签名 TLV **没有由服务器验签**，真实性由本项目外置签名清单验证；Bootloader 仍须按它自己的信任策略验签。原始 Cortex-M 文件不是随便选一个 STM32 型号就能升级。未知格式一律拒绝，不降级为“只检查扩展名”。

相邻 `00_BASIC` 工程已接入个人 OTA 协议；V1.0.7 新增网页远程升级和重启的设备执行端。服务器更新不会自动烧录板子，远程命令须设备更新后才可用。其他 MCU 接入时仍需实现设备凭据、签名清单、下载与启动确认，见 [协议文档](docs/protocol.md)。

## 1. 首次安装和运行

需要 Python 3.11 或 3.12，以及 Git。仓库已包含构建好的 Vue 前端，直接运行后端即可打开管理网页。

在 Windows PowerShell 中执行下面的命令。

```powershell
git clone https://github.com/ricarrdooo/my-ota-server.git
Set-Location my-ota-server
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m ota_server init
.\.venv\Scripts\python.exe -m ota_server serve
```

初始化时设置管理员密码，至少 12 个字符。默认用户名为 `admin`。浏览器打开 [本机后台](http://127.0.0.1:8000)。以后可运行 `scripts/start.ps1`。

Linux / macOS 的启动命令如下。

```sh
git clone https://github.com/ricarrdooo/my-ota-server.git
cd my-ota-server
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m ota_server init
.venv/bin/python -m ota_server serve
```

数据库、设备凭据、固件、签名私钥和部署配置由你在本机创建，已通过 `.gitignore` 排除。管理员密码在初始化时自行设置。

默认只监听本机，不是手机访问地址。本机 HTTP 仅供开发；不要把 8000 端口裸露公网。更改本机端口时同时设置 `OTA_PUBLIC_URL`，或用 `scripts/start.ps1 -Port 8080`。

### ESP32 在可信局域网联调（显式开启）

默认不开放局域网 HTTP。需要让 ESP32 连接这台开发电脑时，在电脑上运行：

```powershell
# 在仓库根目录运行
$env:OTA_PUBLIC_URL='http://127.0.0.1:8000'
.\scripts\start.ps1 -LanIP 192.168.10.187
```

`192.168.10.187` 是电脑 Wi-Fi 地址的示例；换网络/IP 后要改成本机实际私网 IPv4。
也可直接执行 `python -m ota_server serve --lan-http-host 192.168.10.187 --port 8000`，
或显式设置 `OTA_LAN_HTTP_HOST`。程序只绑定 `127.0.0.1` 和指定私网 IP，不监听全部网卡。
管理员后台仍在电脑浏览器打开 `http://127.0.0.1:8000`，保留 Web Crypto 本地签名的安全上下文；
**手机/其他电脑不能通过此调试入口登录管理员后台**。

设备页填写 `http://192.168.10.187:8000`、平台设备标识及对应访问密钥，勾选“允许内网 HTTP 调试”并保存。
地址不带 `/api` 或末尾斜杠。首次配置时填写对应密钥。地址变化后能否沿用密钥，取决于设备客户端实现；本项目 ESP32 客户端支持保留已保存密钥。
用手机（和设备同一个网络）打开 `http://192.168.10.187:8000/healthz` 应返回 `status=ok`；
这只验证手机到服务的连通性。实际 ESP32 连接以平台设备“最近联系”持续更新和当前固件上报为准。
终端会打印设备接口的方法、路径、来源 IP 和响应码，不记录访问密钥、请求体或查询参数。
未鉴权的设备请求返回 401 仍能证明接口可达；不要据此声称设备已认证。

LAN 仅放行健康检查与现有五类设备 API，继续验证 Bearer 凭据；后台、登录、静态文件拒绝。
校验真实 TCP 两端、Host/端口和可选 Origin，不信任代理转发头。
RFC1918 之外的来源和监听地址被拒绝；该模式不能和公网 HTTPS 模式同时启用。
HTTP 会明文传输设备凭据，仅限可信网络短期联调；不要做路由端口映射或对外代理。
启动脚本不修改 Windows 防火墙；若本机可访问而手机不可访问，需核对网络隔离/防火墙。
正式部署仍使用下文 Caddy HTTPS，不使用此模式。

找回管理员密码（在服务器本机）：`python -m ota_server reset-admin`，会注销全部登录会话。初始化也支持环境变量 `OTA_ADMIN_PASSWORD` 供部署脚本使用，使用后立即清除；不要写进 `.env` 或命令历史。

## 2. 发布固件（推荐网页一键打包）

### Vue 桌面界面与本地构建

管理页面已迁移至 Vue 3 单文件组件，以电脑使用为主，验证宽度为 1280、1440、1920；
未单独适配手机。六个页面支持响应式数据更新，固件/发布/设备等列表提供即时搜索和状态筛选，
定时刷新保留当前筛选。状态标签、设备选择与说明文字使用明确的布局间距，不依赖负边距。

当前外观使用暖白纸面与松绿强调色，暗色模式对应石墨绿灰；导航与统计使用自带线性 SVG 图标。
登录页、表格、状态标签、按钮与弹窗使用同一套配色和层级，不加载外部字体、图片或图标 CDN。
主题选择和本机签名权限不变，仅调整外观，不改变发布、删除、鉴权或设备协议。

前端源码位于 `frontend/src`，包含页面、共享组件和管理控制桥接；
`ota_server/static/admin/admin.js`、`admin.css` 是已生成的生产资源，随 Python 服务同源提供。
页面不依赖 CDN，运行服务器不需要额外启动 Node/Vite，也不需要为前端新增公网端口。
原本机签名 Worker、IndexedDB 签名权限与原生管理弹窗通过受控桥接继续使用，
没有清空本机密钥记忆或改变设备 API，也未放宽 CSP。

仅当修改前端源码或生成资源缺失时需要重新构建（当前验证 Node.js 24.19）：

```powershell
# 在仓库根目录运行
.\scripts\build-ui.ps1
# 已安装锁定依赖时，只重新构建：
.\scripts\build-ui.ps1 -SkipInstall
```

等价于在 `frontend` 执行 `npm ci` 和 `npm run build`；依赖版本由 package-lock.json 锁定。
构建只替换专用 `ota_server/static/admin`，不会清空签名模块、固件目录或数据库。
Dockerfile 也加入前端构建阶段。修改后浏览器 Ctrl+F5 即可更新静态界面；
若仍提示后台接口版本不一致，需按原方式重启 Python OTA 服务，ESP32 不用重新烧录。

构建方式参考 [Vue 单文件组件](https://vuejs.org/guide/scaling-up/sfc.html) 与
[Vite 构建配置](https://vite.dev/config/build-options.html)。

### 首次准备

日常界面已精简：不显示框架技术标签；固件摘要只在构建信息中展示一次，悬停可查看完整值。
基础硬件与设备配置完成后，总览不再重复显示入门步骤；帮助入口仍保留。
高级三文件上传统一放在“打包并上传”窗口底部，不再单独占用日常页面按钮。
网关、STM32/MCUboot 兼容能力以及所有安全保护没有删除；配置、记录和本机签名权限不变。

1. 登录，创建产品，例如 `desk-monitor`。
2. 在可信电脑生成一次密钥；已经生成过就继续使用原密钥，不要重新生成：

   ```powershell
   .\.venv\Scripts\python.exe -m ota_server keygen --output private/desk-monitor
   ```

   设置私钥保护密码；只把 `public.pem` 内容添加到后台，`private.pem` 留在可信电脑并另行离线备份。同一公钥只属于一个产品。
3. 创建精确硬件型号。创建后不可修改；布局、公钥、容量或安全要求变化需新增型号。只勾选实机已实现的能力，不能虚报“自动回滚”。
4. 添加设备，选择正确型号和 stable / beta 通道，安全保存一次性显示的设备 ID 与访问密钥，用于后续客户端接入。**设备访问密钥不是签名私钥，也不是管理员账号。**

### 首次在当前浏览器导入签名权限

打开“打包并上传”，选择已登记设备，展开“首次导入签名私钥”，选择与该型号公钥配对的
`private.pem` 并点“导入并记住”。未加密 PEM 无需密码；已有加密 PEM 首次仍需原密码解锁，
不能跳过解密。导入后不保存原 PEM 或保护密码，也不将私钥传给服务器。
浏览器使用 IndexedDB 按公钥指纹保存不可导出的 RSA-PSS CryptoKey；相同签名公钥的型号可复用。

这会长期保留可用签名权限，只有在你信任的个人电脑上使用。不可导出不等于绝对安全：
仍需信任同源网页代码、浏览器及本机账户。请另行离线备份原私钥；浏览器数据不是备份。
换电脑、换浏览器、改变站点地址/端口或清除网站数据后需重新导入。
可点“移除本机记忆”删除此浏览器内该公钥的签名权限，不会删除原私钥文件或吊销平台公钥。

### 日常操作：选设备 → 选 bin → 写说明 → 确认发布

1. 正常编译得到应用 `.bin`。打开后台“固件文件”，点击“打包并上传”。
2. 选择设备、应用 bin 并填写更新说明。已导入签名权限的浏览器无需再次选择私钥或输入密码。
   型号和默认通道从设备读取；高级选项可改通道。ESP / MCUboot 版本从镜像自动读取，原始 Cortex-M 文件仍需填写版本。
3. 点击“打包并上传”。网页自动读取型号配置，不需要导出 / 选择 profile.json；本机 Worker 检查镜像、
   计算完整 bin 的 SHA-256，使用本机保存的 CryptoKey 完成 RSA-PSS 签名，并用目标公钥复验后才允许上传。
4. 浏览器只上传固件、manifest.json、signature.txt 和更新说明。服务器独立复核；成功后会显示版本、大小与摘要，可下载清单和签名留档。
5. 检查结果，点击“确认发布到 stable / beta”。**打包与上传不会自动发布。** 也可点击“暂不发布”，稍后在固件库发布。

非敏感的设备/通道选择保存在 localStorage，签名 CryptoKey 仅保存在当前站点的 IndexedDB，不把 PEM、
密码或 CryptoKey 放进上传请求。首次密码错误、错私钥、格式或容量错误会在本地阻止操作。
取消会停止本地等待 / 工作线程；若服务器已经开始接收上传，取消不保证撤销已入库记录，
请在固件库核对，不会自动发布。选设备仅用于确定型号/通道，发布会影响同型号、同通道的其他设备。

本地签名需要 HTTPS 或电脑上的 `http://127.0.0.1` / localhost，普通局域网 HTTP 不支持。支持本项目生成的口令保护 PKCS#8（PBES2 / PBKDF2 / AES-CBC），以及未加密 PKCS#8、未加密 PKCS#1 RSA-3072/4096。OpenSSH、传统加密 RSA PEM 等格式会明确拒绝；需先在可信电脑转换为匹配原公钥的 PKCS#8，或使用支持其格式的离线工具，不可重新生成无关密钥冒充原私钥。

“浏览器本地签名”不等于“严格离线”：仍需信任服务器下发的网页代码。项目不使用第三方 CDN 或在线签名服务，也不会将私钥 / 密码加入请求；如果要求与公网网页隔离，请采用下面的离线方式。

管理后台和登录页支持明暗主题切换；首次跟随系统，手动选择后由当前浏览器记住。主题偏好不含密钥。

### 固件手动管理（不限制保留份数）

已取消“最近 5 份”规则和批量清理入口。上传、启动、打开页面都不会自动删除固件，
可以自行决定保留多少版本。“固件库”的“操作”列同时提供“发布此固件”和“删除此固件”。
点删除后先显示选中版本、硬件型号、完整 SHA-256 与预计释放空间，再明确确认；取消不修改任何数据。

只能删除当前点选的一份，不会顺带清理其他版本。活动发布须先在“版本发布”中撤回；
非终态升级、仍在 24 小时下载授权期内的升级尝试、实际 HTTP 文件流均受保护。
确认时服务器重新检查使用状态和文件状态，预览过期需重新打开删除窗口。
共享 SHA-256 文件只有最后一个可用引用被删除时才释放，因此删除一个版本可能释放 0 字节。

删除成功后该版本从固件库移除，但版本元信息、签名清单、发布和升级历史保留。
已删除文件没有回收站，不能直接重新发布；重新上传相同原固件可恢复。
元信息先事务提交，再移除文件；若被占用等导致释放失败，该行标记“文件待释放”，可点“重试删除文件”。
不扫描删除未知文件，不做全目录清空，不会批量处理其他已删除版本留下的文件。

文件操作保护依赖现有单实例、单进程部署契约，不支持多 workers 或多个应用实例共享目录。
不要同时执行删除和 CLI 备份；备份保留已删除版本的历史，但只复制仍可用的固件文件。
更新代码后需重启 OTA 服务，再刷新后台；不会自动对当前存储执行删除。

### 产品、硬件与其他资料管理

“产品与硬件”和“设备与网关”页面已提供编辑、删除入口；标识不可编辑，每次删除均需确认。

| 对象 | 可编辑内容 | 删除限制 |
| --- | --- | --- |
| 产品 | 名称、说明 | 有硬件型号或公钥时拒绝删除 |
| 硬件型号 | 显示名称 | 有设备、固件元信息或发布历史时拒绝删除 |
| 签名公钥 | 名称 | 有硬件型号或固件元信息引用时拒绝删除；在用公钥可吊销 |
| 设备 | 名称 | 有升级历史时拒绝删除；删除无历史直连设备会移除其凭据 |
| 网关 | 名称 | 有授权子设备时拒绝删除；删除空网关会使其凭据失效 |

硬件的 MCU、修订、分区布局、容量、适配器配置、签名公钥及能力等兼容参数仍不可变，
变更这些参数应新增型号，不覆盖旧型号；改显示名称不会改变配置指纹或影响原固件签名。
子设备改名不会改共享网关名称，删除子设备不会删除网关凭据。
删除被引用的记录会明确显示关联数量，不支持“强制/级联删除”，以免破坏现有设备和历史。
删除无引用的型号、公钥后才能继续删除其产品；已有历史应保留，不因固件文件删除而绕过保护。
所有变更仍要求管理员登录、CSRF 与来源检查，并记录审计。

### 版本发布管理

“版本发布”的“操作”列提供编辑说明、撤回 / 重新发布、删除发布。

- **编辑说明**：只修改这一条发布的说明，不改变固件库说明、版本号、摘要、签名、板型或通道。
  新建发布默认带入固件库说明，也可在发布前填写独立说明，最多 2000 字；留空可明确清空。
- **撤回 / 重新发布**：撤回阻止新的升级尝试，已有绑定下载仍按原授权继续。
  重新发布默认带入原通道和原发布说明，确认后创建新发布和更高序号，不是修改旧记录。
- **删除发布**：先确认具体版本、型号、通道与序号，只移除选中的发布，不删除固件文件，
  不会回退已安装设备。活动发布须先撤回；已有任何升级记录（包括成功或失败历史）时禁止删除。
  如需回收 bin 空间，请另行在“固件文件”中手动删除。

删除后该条发布不再显示，也不能再通过其 ID 编辑、撤回或开始升级。
内部保留序号与审计信息，确保之后发布不会重复使用已删除的序号；没有级联删除或强制删除。
新增兼容表在重启服务时自动创建，旧发布说明自动沿用固件说明；无需手动改库或重新烧录设备。

### 固件状态与后台更新提示

固件与发布列表现在同时显示短 SHA-256、制品 ID 和独立的文件状态。
**相同版本号不等于相同固件**：版本相同但摘要不同的构建仍是不同文件，不会一起删除。
删除某个制品后，所有关联这个制品 ID 的发布都同步显示“固件已删除”；
已撤回、没有升级记录的发布仍能删除，不受它的固件文件是否已经删除影响。
文件状态与操作按钮分列显示，使用电脑端表格布局，明暗主题均保留；当前 Vue 版本不单独适配手机。

列表区分“文件可用 / 固件已删除 / 文件缺失 / 校验异常 / 存储不可读”，
缺失或损坏不再显示为可发布。列表校验有有界缓存，真正发布和下载仍完整验证文件，不能绕过校验。
存储读取失败不会冒称文件已删除，也不会自动归档或删除；占用统计不完整时会明确提示。

若点击管理操作看到 **Not Found**，可能是磁盘上的网页已更新，但运行中的 Python 进程仍是旧接口。
页面现在会与后台做能力检查，不匹配时显示“后台需要重启”，进入只读模式；业务上的“记录已删除”
与“后台缺少接口”会分别解释，不再只显示相同的英文报错。

更新后的正确步骤：

1. 确认没有设备正在进行 OTA。在原来运行后台的终端按 Ctrl+C，结束旧 OTA 服务。
2. 按原启动命令重新启动，保持原有端口、LAN IP 等参数不变。只关闭浏览器标签不算重启后台。
3. 浏览器按 Ctrl+F5 强制刷新；后台兼容时只读提示自动消失。ESP32 不用重新烧录。

管理刷新会等待变更后的新快照，定时轮询不会吞掉删除后的刷新；
关闭或切换弹窗后，迟到的删除/查询响应不会关闭或覆盖新窗口。

### 高级 / 严格离线方式

在“产品与硬件”导出配置，用原命令行工具打包：

```powershell
.\.venv\Scripts\python.exe -m ota_server pack --profile desk.profile.json --firmware app.bin --private-key private/desk-monitor/private.pem --output dist/release-001
```

原始 Cortex-M 需要额外 `--version 1.0.0`，每次使用新输出目录。在“打包并上传”窗口底部选择“使用高级三文件上传”，可提交原始 bin、manifest.json、signature.txt。命令行不会修改原固件，ESP / MCUboot 版本必须与镜像内置版本相同。

ESP32-S3 当前工程的 UI 预设为 chip_id=9、项目名 `00_BASIC`、3 MiB 单 OTA 槽，仍要按实际分区表确认。上传应用 `.bin`，不是 bootloader、合并整包或整个 flash dump。

签名工具与校验器都拒绝不匹配文件。版本号用于展示，是否需要更新用已安装制品的 SHA-256 判断；不会假装支持所有语义版本排序。重新发布旧制品是显式的管理操作，不等于已实现硬件防降级。

更新判据已固定为**整个已安装 `.bin` 文件的 SHA-256**：相同则不更新，不同则提供当前活动发布；即使版本号没改也可发现不同文件。设备不知道当前摘要时省略 `current_sha256`，不能用空字符串、ELF 摘要或服务器旧心跳记录代替。版本号仍需与镜像自身一致，也用于启动确认，但不参与新旧排序。设备需在完整下载验签、校验与安装后，将摘要绑定对应槽位保存，待新应用启动确认后再作为当前已安装摘要上报；失败或回滚不能保留新包的摘要冒充正在运行版本。

## 3. 部署到你自己的公网服务器

### 免费临时入口：本机 Windows + Cloudflare Quick Tunnel

无需云服务器或域名，数据继续保存在本机；电脑、后台和隧道必须持续运行。
这是临时测试入口，重建隧道会更换 HTTPS 地址，不作为固定的长期 OTA 地址。

Windows 上双击桌面的 **OTA 公网地址** 或项目中的 `OTA公网地址.exe`，等窗口显示验证成功，再点 **复制地址**。将它粘贴到 ESP32 的「个人 OTA 服务器 → 服务器地址」。关闭窗口后，电脑仍会提供公网服务。再次双击可以找回当前地址；点 **停止公网** 可结束隧道。原本运行的是本项目默认本机后台时，窗口会在停止公网或启动失败后恢复它。换电脑后，在安装项目依赖的基础上运行 `scripts/build-public-window.ps1` 可重新生成 EXE 和桌面快捷方式。

也可以使用命令行。先在原后台终端按 Ctrl+C 停止旧实例，再在项目目录运行：

```powershell
.\scripts\start-public.ps1
```

脚本首次下载 Cloudflare 官方 Windows x64 便携版（固定版本 2026.10.3），核对发布页 SHA-256；
工具与运行日志保存在已忽略的 `.cache/`，不安装系统服务，不改防火墙、路由器或现有 Cloudflare 配置。
随后取得 `https://随机名称.trycloudflare.com`，为唯一后台设置精确 `OTA_PUBLIC_URL`，
只监听 `127.0.0.1`，关闭局域网 HTTP 调试，仅信任回环代理；现有 Host/Origin、登录、CSRF、签名保护不变。
未初始化管理员、端口被占用或已有本启动器运行时会拒绝启动。
不要通过更换端口并发启动另一个使用相同数据目录的后台。

只有公网健康检查、带 Secure/HttpOnly/SameSite Cookie 的登录页，以及未登录管理接口返回 401 均通过后，
才打印 `PUBLIC_URL=...` 并将 `.cache/quick-tunnel.json` 标记为 `ready`。
使用该地址和原管理员账户登录；设备 OTA 服务器地址也填写这个 HTTPS 根地址。
设备密钥、型号、公钥与固件数据沿用，不自动修改或烧录设备。
浏览器签名权限按网站来源隔离：临时域名改变后需要首次重新导入私钥；私钥仍不上传服务器。

保持启动终端运行；停止时按 Ctrl+C，或在另一个终端运行：

```powershell
.\scripts\stop-public.ps1
```

停止脚本请求启动器关闭自己创建的后台和隧道，不终止其他 Python 任务，也不自动重启原本机后台。
需要恢复本机模式时再运行 `.\scripts\start.ps1`。请在没有正在下载的 OTA 时切换/停止服务。
默认使用已在实际入口验证通过的 `auto`：优先 QUIC，必要时回退 HTTP/2；
排查网络时可显式使用 `-Protocol http2` 或 `-Protocol quic`，不会禁用 TLS 校验。
在 Windows 上自动沿用已启用的系统 HTTP/HTTPS 代理（显式代理环境变量优先），不会改动系统设置；
回环健康检查始终直连。浏览器能上网不代表隧道到 Cloudflare 边缘的 TCP/UDP 7844 一定畅通。
工具预下载可使用 `-PrepareOnly`，该选项不停止现有后台，也不开放服务。

官方说明：[Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)、
[便携工具及发布校验值](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.3)。

### 固定域名 + Linux 云服务器

准备一台运行 Docker Engine + Compose v2 的 Linux 服务器，一个解析到该服务器的域名，以及可访问的 TCP 80 / 443。若发布 AAAA 记录也必须保证 IPv6 路径有效。这里不预设云厂商和付费规格。

把本目录代码传到服务器；**排除 `.venv`、`private`、`data`、`.env`、测试截图及本机密钥**。在服务器项目目录执行：

```sh
cp .env.example .env
# 编辑 .env，改成你自己的域名，例如 OTA_DOMAIN=ota.your-domain.com
docker compose build
docker compose run --rm app python -m ota_server init
docker compose up -d
docker compose ps
docker compose logs --tail=80 app caddy
```

访问 `https://你的域名`。Caddy 使用持久卷保存自动 HTTPS 证书；只暴露 80 / 443，app 的 8000 端口仅在 Compose 内部网络可达。首次初始化密码在 `run` 交互终端输入。**域名仍为示例时不要直接启动公网部署。**

已提供配置，但当前开发机未安装 Docker，未实际构建 Linux 镜像、签发证书或部署公网实例；这部分需要在你的服务器上验收。部署前应确认镜像可拉取、pip 源可访问、DNS 与防火墙正常。

### 重要配置

| 配置 | 默认 / 用途 |
| --- | --- |
| `OTA_PUBLIC_URL` | 本机 `http://127.0.0.1:8000`；公网必须是精确的 `https://域名`，不带路径 |
| `OTA_DATA_DIR` | 本机 `data`；容器 `/data`，包含数据库、固件和暂存文件 |
| `OTA_MAX_UPLOAD_BYTES` | 默认 33554432，单文件 32 MiB，全局上限 128 MiB |
| `FORWARDED_ALLOW_IPS` | 本机默认 `127.0.0.1`；Compose 内部信任 Caddy，不能给裸露公网的 app 设 `*` |

修改上传上限还需同步 Caddyfile 的请求体限制（当前 34 MB，用于默认 32 MiB 固件加 multipart 开销）。限流保存在进程内，SQLite 发布事务按单实例实现；不要自行增加多个应用副本 / workers 后宣称限流与发布一致性不变。

`OTA_PUBLIC_URL` 要与访问地址一致，否则 Host / Origin / Cookie 检查可能阻止登录。公网 HTTPS 下 Cookie 带 Secure，不能通过 HTTP 登录绕过。设备必须校验 HTTPS 证书，不允许“忽略证书错误”。

## 4. 备份 / 恢复

本机备份（输出必须是新目录）：

```powershell
.\.venv\Scripts\python.exe -m ota_server backup --output F:/OTA-Backups/2026-10-23
```

容器备份到**独立宿主机目录**，使用容器用户 UID 10001 可写目录：

```sh
sudo install -d -o 10001 -g 10001 -m 700 /srv/ota-backups
docker compose run --rm -v /srv/ota-backups:/backup app python -m ota_server backup --output /backup/snapshot-2026-10-23
```

在线数据库使用 SQLite backup API 获取一致快照，然后复制该快照引用的不可变固件并检查摘要。失败会返回非零并可能留下不完整的新备份目录；不要将其当成成功快照。备份包含账户与设备凭据哈希，按敏感数据保管；签名私钥需另行离线备份。

恢复前停止 app，先备份当前数据。将已验证快照的 `ota.sqlite3` 和整个 `firmware/` 放入**空的新数据目录 / 新数据卷**，创建空 `staging/` 并赋予 app 用户读写权限，再挂载该目录启动。不要把新数据库混进旧 WAL/SHM 文件中。恢复后先重置管理员密码注销旧会话，再抽查固件摘要、设备和发布记录。不要执行 `docker compose down -v`，这会删除数据卷。

密钥吊销会阻止相关固件检查、发布和下载，但不是向已离线设备即时撤回其本地信任。首版没有自动公钥轮换链，换根密钥需要单独规划设备信任迁移。
